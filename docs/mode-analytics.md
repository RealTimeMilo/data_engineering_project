# Mode Analytics → Analytics Postgres

A dedicated PostgreSQL instance holds pipeline telemetry for Mode. It is
**publicly reachable but IP-allowlisted to Mode's eight Direct Connect egress
addresses**, with TLS enforced (`rds.force_ssl=1`).

## Infrastructure

`terraform/analytics.tf` creates:

| Resource | Name |
|---|---|
| RDS instance (`db.t3.micro`, 20 GiB, Postgres 16) | `sde-airflow-dev-analytics-pg` |
| Database | `analytics` |
| Schema | `ml_analytics` |
| Bootstrap task | `sde-airflow-dev-ml-analytics-bootstrap` |

Mode is allowed on 5432 only from:

```
54.68.30.98/32   54.68.45.3/32     34.209.23.118/32  54.188.241.100/32
52.43.195.103/32 3.224.146.111/32  54.221.238.89/32  52.20.173.236/32
```

All other internet traffic is dropped by the security group. The ML/Airflow
security groups are separately allowed for in-VPC writes.

## Roles

| Role | Used by | Permissions |
|---|---|---|
| `analytics_admin` | bootstrap task only | RDS master |
| `ml_writer` | ECS pipeline | SELECT/INSERT/UPDATE/DELETE on `ml_analytics` |
| `mode_readonly` | Mode Analytics | SELECT only; `default_transaction_read_only=on`; 120 s statement timeout |

Passwords are generated by Terraform and stored as SSM `SecureString`s. The
Mode credentials are exposed as sensitive Terraform outputs:

```bash
terraform -chdir=terraform output -raw analytics_db_endpoint
terraform -chdir=terraform output -raw analytics_mode_user
terraform -chdir=terraform output -raw analytics_mode_password
terraform -chdir=terraform output -raw analytics_connection_url
```

## Schema

```
ml_analytics.pipeline_runs
    run_id, dag_id, status, params (jsonb), mlflow_run_id, started_at, finished_at
ml_analytics.model_metrics
    run_id, stage, metric, value, recorded_at          UNIQUE(run_id, stage, metric)
ml_analytics.model_predictions
    run_id, user_id, product_id, label, reorder_probability, scored_at
                                                       UNIQUE(run_id, user_id, product_id)
```

`evaluate.py` publishes every scored test pair (≈8.8k rows per run), and
`train.py` / `evaluate.py` / `deploy.py` upsert metrics, so re-running a stage is
idempotent.

## Bootstrap (once per stack)

The RDS instance is created by Terraform, but the schema and roles are created by
a one-off ECS task (the training image already contains `bootstrap_analytics.py`):

```bash
make analytics-bootstrap
```

It is idempotent and prints the tables and row counts. After the first pipeline
run, `pipeline_runs`, `model_metrics`, and `model_predictions` are populated.

## Mode connection

In Mode: **New → Data source → PostgreSQL**

| Field | Value |
|---|---|
| Host | `terraform output -raw analytics_db_endpoint` |
| Port | `5432` |
| Database | `analytics` |
| Username | `mode_readonly` |
| Password | `terraform output -raw analytics_mode_password` |
| SSL | enabled (required) |

Mode validates the connection from its own egress IPs, so it must be created
from Mode's UI (not from a local `psql`, which is not allowlisted).

## Example queries

```sql
-- Latest model metrics, one row per metric
SELECT run_id, stage, metric, value, recorded_at
FROM ml_analytics.model_metrics
WHERE run_id = (SELECT run_id FROM ml_analytics.pipeline_runs
                ORDER BY started_at DESC LIMIT 1)
ORDER BY stage, metric;

-- Score distribution for the most recent run
SELECT width_bucket(reorder_probability, 0, 1, 10) AS decile,
       count(*) AS pairs,
       avg(label) AS observed_reorder_rate,
       avg(reorder_probability) AS mean_score
FROM ml_analytics.model_predictions
WHERE run_id = (SELECT run_id FROM ml_analytics.pipeline_runs
                ORDER BY started_at DESC LIMIT 1)
GROUP BY 1 ORDER BY 1;

-- Top products by predicted reorder volume
SELECT product_id,
       count(*) AS pairs,
       avg(reorder_probability) AS mean_score,
       sum(reorder_probability) AS expected_reorders
FROM ml_analytics.model_predictions
WHERE run_id = (SELECT run_id FROM ml_analytics.pipeline_runs
                ORDER BY started_at DESC LIMIT 1)
GROUP BY product_id
ORDER BY expected_reorders DESC
LIMIT 25;
```

## Security notes

- The database is public by necessity (Mode Direct Connect cannot SSH-tunnel);
  the allowlist is the network control.
- `mode_readonly` cannot write even if a query tries: the role starts read-only
  transactions and has no INSERT/UPDATE/DELETE grants.
- Rotate the Mode password by tainting `random_password.analytics_mode`, applying,
  and re-running `make analytics-bootstrap` (it is idempotent and updates the
  role password).
- To add another client, extend the `aws_security_group.analytics_rds` ingress
  list in `terraform/analytics.tf`; do not broaden it to `0.0.0.0/0`.
